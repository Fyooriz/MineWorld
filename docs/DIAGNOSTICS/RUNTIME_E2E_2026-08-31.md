# Runtime E2E Diagnosis — 2026-08-31

## Observed

The `real-input-e2e` job built `MineWorld.Playable` successfully, found the `MineWorld P0` window, and confirmed that the target window was active. It then failed with `REAL_INPUT_E2E: craft input not observed` and exited with code 8.

## Evidence

- Window discovery succeeded.
- Active window ID matched the discovered MineWorld window.
- No application build error occurred before the input phase.
- Raylib initialized successfully with the Mesa llvmpipe renderer.
- The workflow sent a one-shot `xdotool key ... c` event before waiting for the `craft=true` log marker.

## Root-cause classification

**High-confidence: test-harness/input-delivery flakiness, not a confirmed gameplay failure.**

The workflow exercised an edge-triggered `IsKeyPressed(C)` check using a single synthetic key event. A one-shot X11 event can be missed by the application's polling boundary even when the window is focused. The captured run does not prove that the C event reached the Raylib input state, and it does not show a gameplay exception.

## Corrective action

The E2E workflow now sends an explicit key-down, holds the key for 350 ms, then sends key-up. The same approach is used for F5. The runtime input logger also records `craft_down` during runtime E2E, improving discrimination between OS input delivery and edge-trigger detection.

## Remaining uncertainty

The corrective change is not yet verified against a post-change GitHub Actions run in this repository state. Until that run completes successfully, the real-input E2E status remains **NOT VERIFIED**.
